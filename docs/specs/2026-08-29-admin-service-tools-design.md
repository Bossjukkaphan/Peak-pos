# เครื่องมือแอดมินให้บริการลูกค้า (A/B/C) — Design

> อนุมัติทิศทางโดย Boss 29 ส.ค. 2026: ทำทั้ง A → B → C ต่อเนื่อง
> เป้าหมาย: แอดมินหน้าร้านทำงานเร็วขึ้นทั้งบนมือถือและ PC โดยไม่เพิ่ม dependency ใหม่
> (คง pattern เดิม: server components + server actions + `<details>` แทน client JS)

## A. ค้นหาเร็ว + การ์ดเด็ก (`/find`)

**ปัญหา:** ช่วงพีคหลังเลิกเรียน เด็กเข้าพร้อมกันหลายคน การเช็คอินต้องไปหา booking
ในตารางเทรน และคำถามผู้ปกครอง (ครั้งเหลือ/หมดอายุ) ต้องเปิดหน้าโปรไฟล์ทีละคน

**ออกแบบ:**
- ช่องค้นหาใน topbar (GET form → `/find?q=…`) ใช้ได้ทุกหน้า ทั้งมือถือ/PC ไม่พึ่ง JS
- ค้นจาก: ชื่อเล่น/ชื่อจริง/รหัส PL ของเด็ก · ชื่อ/เบอร์ผู้ปกครอง · ชื่อ/เบอร์ lead
- ผลลัพธ์เป็น **การ์ดเด็ก** ใบเดียวจบ:
  - ชื่อเล่น (รหัส) · ธงแดงถ้าครั้งเหลือ ≤ threshold หรือคอร์สใกล้หมดอายุ (≤30 วัน)
  - **ข้อระวัง/โรคประจำตัว เด่นชัด** (กรอบแดง)
  - ครั้งคงเหลือรวม + วันหมดอายุของคอร์ส active · เบอร์ผู้ปกครอง (ลิงก์ `tel:`)
  - นัดวันนี้ (ถ้ามี) + ปุ่ม **เช็คอิน** ตรงนั้นเลย (ใช้ action `checkIn` เดิม)
  - ไม่มีนัดวันนี้ → ฟอร์มย่อ **เช็คอิน walk-in**: เลือกโค้ช + เวลา (default slot ปัจจุบัน)
    → action ใหม่ `walkInCheckIn` สร้าง booking แล้วเช็คอินใน transaction เดียว
  - ลิงก์ต่อ: โปรไฟล์เต็ม · ขายคอร์ส/ต่อคอร์ส (`/pos?member=…`)
- ผล lead แสดงการ์ดย่อ: ชื่อ/เบอร์/สถานะ + ลิงก์ไปหน้า Trial

## B. ตารางเทรนขั้นสอง: จองประจำ · ความจุ+waitlist · เลื่อนนัด

**จองประจำ (ธรรมชาติยิมเด็กคือนัดรายสัปดาห์):**
- ฟอร์มเพิ่ม Booking มีช่อง "จองประจำทุกสัปดาห์ … สัปดาห์" (1–52)
- action `createBooking` เดิมรองรับ: วนสร้างรายสัปดาห์จากวันแรก ผูก `recurring_group`
  (คอลัมน์ใหม่ใน bookings) · สัปดาห์ที่ชนวันหยุดโค้ช **ข้ามและรายงาน** ให้แอดมินเห็น
  (ไม่เดาห้องแทนคน) · แสดงผล "จองแล้ว n นัด ข้าม m นัด (วันที่…)"
- ยกเลิกทั้งชุด: ปุ่ม "ยกเลิกนัดประจำที่เหลือ" บน chip (ยกเลิกเฉพาะ booked ในอนาคต)

**ความจุต่อ slot + waitlist:**
- setting ใหม่ `slot_capacity` (default 2 ตามชีทวางแผน — แก้ได้หน้าตั้งค่า)
- จองเมื่อช่วงเวลาทับกันของโค้ชนั้นเต็ม → บันทึกเป็น `status='waitlist'` แสดง chip
  สีเหลืองในช่องเดียวกัน พร้อมปุ่ม "รับเข้า slot" (ตรวจความจุซ้ำก่อนเปลี่ยนเป็น booked)
- นัดประจำ: สัปดาห์ที่เต็มเข้า waitlist อัตโนมัติ (นับรวมในรายงานผลการจอง)
- แก้ query board/ตารางที่ใช้ `status!='cancelled'` ให้ไม่นับ waitlist เป็นนัดจริง

**เลื่อนนัด:**
- บน chip (สถานะ booked/waitlist) มี `<details>` "เลื่อน" กางฟอร์ม วันที่/เวลา/โค้ช
  → action `rescheduleBooking` ย้ายนัดเดิม (แถวเดิม id เดิม) พร้อมต่อท้าย note
  "เลื่อนจาก วันที่ เวลา" · ถ้าช่องใหม่เต็มให้เข้า waitlist พร้อมแจ้ง
- แตะเลือกจาก dropdown ใช้ได้ทั้งนิ้วและเมาส์ — ไม่ทำ drag & drop ในเฟสนี้

## C. หน้า "วันนี้ต้องคุย" (`/calls`)

รวมงานเชิงรุกที่กระจายอยู่หลายหน้าเป็น to-do เดียว เรียงตามความเร่ง:
1. **ตามต่อ 1-2-3 ถึงกำหนด/เลยกำหนด** (followups ที่ยังไม่ done) + ปุ่มบันทึกผลเดิม
2. **ครั้งเหลือ ≤ threshold** (enrollment active) — โอกาสต่อคอร์ส
3. **คอร์สหมดอายุใน ≤30 วัน** และยังมีครั้งเหลือ
4. **หายไป ≥14 วัน** (สมาชิก Active มีครั้งเหลือ แต่นัด attended ล่าสุดเกิน 14 วัน
   หรือไม่เคยมา) — ตามกลับมาเทรน
- ทุกแถว: เบอร์ผู้ปกครองแบบ `tel:` (แตะโทรบนมือถือ) + ฟอร์มย่อบันทึก contact_log
- เพิ่มลิงก์ nav "วันนี้ต้องคุย" และการ์ดสรุปจำนวนบน Dashboard

## ข้อมูล/migration

- `bookings.recurring_group TEXT` (ALTER แบบ guard เหมือน end_time เดิม)
- `settings.slot_capacity` อ่านผ่าน `getSetting('slot_capacity','2')` ไม่ต้อง seed
- สถานะ booking เพิ่มค่า `waitlist` (คอลัมน์ TEXT เดิม)

## สิ่งที่ตั้งใจไม่ทำรอบนี้ (YAGNI)

- Drag & drop เลื่อนนัด (ฟอร์มเลือกช่องครอบคลุมและใช้บนมือถือได้ดีกว่า)
- แจ้งเตือน LINE เมื่อคิวหลุด waitlist (รอเฟส LINE OA ตาม blueprint)
- Auto-promote waitlist เมื่อมีคนยกเลิก (ต้องโทรยืนยันลูกค้าก่อนเสมอ → ให้คนกด)
- ยังไม่แตะเรื่องย้าย Supabase (Boss สั่งพักไว้) — ทุกฟีเจอร์เขียนบน SQLite เดิม
