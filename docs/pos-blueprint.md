# Peak POS — พิมพ์เขียวระบบ POS สำหรับยิมเพิ่มส่วนสูงเด็ก

> เอกสารระดมสมอง/ข้อกำหนดตั้งต้น ต่อยอดจาก Google Sheets วางแผนของทีม
> (ทะเบียนสมาชิก · การขายคอร์ส · สิทธิ์คอร์ส · Dashboard · ตารางเทรนรายวัน · ค่าเทรนโค้ช)

---

## 1. สิ่งที่ระบบปัจจุบัน (Excel) บอกเรา

จากชีทที่ทีมทำไว้ อ่านโครงสร้างธุรกิจได้ดังนี้:

| ส่วนในชีท | สิ่งที่เก็บ | Business rule ที่ซ่อนอยู่ |
|---|---|---|
| ทะเบียนสมาชิก | ข้อมูลเด็ก + ผู้ปกครอง + สุขภาพ (ส่วนสูง/น้ำหนักเริ่มต้น, โรคประจำตัว, ข้อระวัง) + ช่องทางที่รู้จัก | เด็กคือ "ผู้ใช้บริการ" แต่ผู้ปกครองคือ "ผู้ซื้อ/ผู้ติดต่อ" — เป็นคนละคนกัน |
| การขายคอร์ส | วันที่, คอร์ส, ราคา, ของแถม, ช่องทางชำระ (Cash/Card/QR), เลขใบเสร็จ, สถานะ | มีของแถมเป็น "ครั้งฟรี" แถมเข้าไปในสิทธิ์ |
| สิทธิ์คอร์ส | จำนวนครั้งทั้งหมด/ใช้ไป/คงเหลือ, โค้ชผู้ดูแลคอร์ส | **แจ้งเตือนเมื่อเหลือ < 6 ครั้ง** (ฟอนต์แดงในตารางเทรน) |
| Dashboard | สมาชิกทั้งหมด, รายได้เดือนนี้, Booking, Active, คอร์สใกล้หมด | ตัวเลขต้องอัปเดตแบบ real-time ("14.30 เทรนไปแล้ว 21 คน") |
| ตารางเทรนรายวัน | Slot ทุก 30 นาที, โค้ชที่เข้างาน, นักเรียนต่อ slot พร้อมตัวนับครั้ง, ช่อง Consult/ทดลองเรียน | มีกลุ่มผู้เรียน (Teen / NP), สถานะ trial: ซื้อแล้ว/ยังไม่ซื้อ/ยังไม่มา, **ติดตามผลการขาย "ตามต่อ 1-2-3"** พร้อมบันทึกเหตุผล (เช่น "ติดเรื่องเงิน") |
| ค่าเทรนโค้ช | จำนวนเทรนต่อวันต่อโค้ช, อัตราค่าเทรนต่อครั้ง | อัตราต่างกันตามโค้ช (150/240 บาทต่อครั้ง) → มีระดับ/เรทของโค้ช, มีวันหยุดโค้ช |

**โครงสร้างราคา:** 1 เดือน = 8 ครั้ง = 8,000฿ · 3 เดือน = 24 ครั้ง = 24,000฿ · 12 เดือน = 100 ครั้ง = 100,000฿ (เฉลี่ย ~1,000฿/ครั้ง)

**จุดที่ Excel จะเริ่มไม่ไหว:** นับครั้งด้วยมือผิดง่าย, สูตร/merge cell พังเมื่อคนหลายคนแก้พร้อมกัน, ไม่มีสิทธิ์การเข้าถึง (ข้อมูลสุขภาพเด็ก = ข้อมูลอ่อนไหวตาม PDPA), ไม่มี audit ว่าใครแก้อะไร, และไม่มีมุมมองสำหรับลูกค้าเลย

## 2. แนวคิดหลักของระบบ

ระบบนี้ไม่ใช่แค่ "เครื่องคิดเงิน" แต่ต้องครอบวงจรธุรกิจทั้งหมด:

```
Lead → นัด Consult/ทดลองเรียน → ตามต่อ (1-2-3) → ขายคอร์ส
     → จองคิว/เทรน/ตัดครั้ง → วัดผลส่วนสูง → ต่อคอร์ส / บอกต่อ
```

หลักคิด 3 ข้อ:

1. **ผลลัพธ์คือสินค้า** — สิ่งที่ผู้ปกครองจ่ายเงินซื้อคือ "ส่วนสูงที่เพิ่มขึ้น" ดังนั้น Growth Tracking (กราฟส่วนสูงเทียบเกณฑ์มาตรฐาน) คือฟีเจอร์เรือธง ทั้งเพื่อรักษาลูกค้าและเป็นหลักฐานทางการตลาด
2. **เด็กกับผู้ปกครองเป็นคนละ entity** — เด็กหนึ่งคนมีผู้ปกครองได้หลายคน, ผู้ปกครองหนึ่งคนมีลูกหลายคน (โอกาสขายพี่น้อง)
3. **ครั้ง (Session Credit) คือสกุลเงินภายใน** — ทุกอย่างหมุนรอบการเพิ่ม/ตัด/หมดอายุของครั้ง ระบบต้องบังคับกฎอัตโนมัติ ไม่ใช่ให้คนจำ

## 3. มุมผู้บริหาร (Owner / Executive)

### Dashboard ภาพรวม (real-time)
- ยอดขายวันนี้/เดือนนี้ เทียบเป้าและเดือนก่อน, สมาชิก Active, จำนวนเทรนวันนี้ (อัปเดตสด), อัตราการใช้ slot (utilization)
- การ์ดแจ้งเตือน: คอร์สใกล้หมด (≤6 ครั้ง), คอร์สใกล้หมดอายุ, ลูกค้าหายไปนาน (ไม่เข้าเทรน 14 วัน), trial ที่ยังไม่ได้ตามต่อ

### การเงินและบัญชี
- รายงานยอดขายแยกตามคอร์ส/ช่องทางชำระ/พนักงานขาย
- **รายได้รอรับรู้ (Deferred Revenue)** — คอร์สที่ขายแล้วแต่ยังไม่ได้ใช้ครั้ง คือ "หนี้บริการ" ที่ยิมติดลูกค้า ตัวเลขนี้สำคัญมากกับธุรกิจขายคอร์สล่วงหน้า และ Excel ทำไม่ได้
- สรุปค่าคอมมิชชั่น/ค่าเทรนโค้ชอัตโนมัติ (แยกเรทตามโค้ช) พร้อม export ทำเงินเดือน
- ใบเสร็จ/ใบกำกับภาษี (e-Tax invoice), รายงานปิดยอดสิ้นวัน, บันทึกรายจ่ายอย่างง่าย → P&L เบื้องต้น
- รองรับผ่อนชำระ/มัดจำ และติดตามยอดค้างชำระ

### การขายและการตลาด (CRM Analytics)
- **Funnel การขาย:** Lead → นัดทดลอง → มาจริง → ซื้อ — วัด conversion แต่ละขั้น แยกตามช่องทาง (Facebook/IG/LINE/เพื่อนแนะนำ)
- ประสิทธิผลการ "ตามต่อ 1-2-3" — เคสที่ปิดได้หลังตามครั้งที่เท่าไหร่, เหตุผลที่ไม่ซื้อ (เช่น ติดเรื่องเงิน → ยิงโปรผ่อนชำระ)
- อัตราการต่อคอร์ส (Renewal rate), Churn, มูลค่าตลอดชีพลูกค้า (LTV) แยกตามคอร์สแรกที่ซื้อ

### ทีมงานและผลลัพธ์
- ผลงานโค้ช: จำนวนเทรน, อัตราลูกค้าต่อคอร์สของแต่ละโค้ช, คะแนน feedback จากผู้ปกครอง
- **รายงานผลลัพธ์การเติบโต:** ส่วนสูงเฉลี่ยที่เพิ่มขึ้นต่อโปรแกรม — ใช้ทั้งปรับโปรแกรมเทรนและเป็น social proof
- รองรับหลายสาขาในอนาคต, กำหนดสิทธิ์ตามบทบาท (Owner / ผู้จัดการ / หน้าร้าน / โค้ช), Audit log ทุกการแก้ไขเงินและครั้ง

## 4. มุมพนักงานหน้าร้าน (Front Desk + โค้ช)

### POS ขายคอร์ส
- แคตตาล็อกคอร์ส + โปรโมชั่น/ของแถม/ส่วนลด (ต้องมีเหตุผลส่วนลดและสิทธิ์อนุมัติ)
- รับชำระ เงินสด/บัตร/QR PromptPay (สร้าง QR พร้อมยอดอัตโนมัติ), ออกเลขใบเสร็จรันอัตโนมัติ, ส่งใบเสร็จเข้า LINE/Email ผู้ปกครอง
- ขายแบบมัดจำ/ผ่อน, ต่อคอร์ส (renew) ในไม่กี่คลิกพร้อมโปรสำหรับลูกค้าเก่า

### ทะเบียนสมาชิก
- ฟอร์มสมัครครบตามชีทเดิม (ข้อมูลเด็ก, โรงเรียน, สุขภาพ, เป้าหมาย, ผู้ปกครอง, ช่องทางที่รู้จัก) + รูปถ่าย
- **ใบยินยอมผู้ปกครอง (consent) แบบดิจิทัล** — จำเป็นเพราะเก็บข้อมูลสุขภาพของผู้เยาว์
- ผูกพี่น้องไว้ใต้ผู้ปกครองเดียวกัน

### เช็คอินและตัดครั้ง
- เช็คอินด้วย QR/เบอร์โทร/ค้นชื่อ → ตัดครั้งอัตโนมัติ, กันติดลบ, ขึ้นเตือนทันทีถ้าเหลือ ≤6 ครั้งหรือใกล้หมดอายุ (ให้หน้าร้านเปิดบทสนทนาต่อคอร์สได้ตรงจังหวะ)
- บันทึกมาสาย/ไม่มา (no-show) ตามนโยบายที่ตั้งไว้

### ตารางจองและคิว (หัวใจของหน้าร้าน)
- ปฏิทินรายวัน/สัปดาห์แบบเดียวกับชีทเดิม: slot 30 นาที, แถวต่อโค้ช, ความจุต่อ slot
- ลาก-วางเพื่อเลื่อนนัด, จองประจำ (ทุกอังคาร 16:00), waitlist เมื่อ slot เต็ม
- แยกประเภทนัด: เทรนปกติ / Consult / ทดลองเรียน / วัดตัว-ประเมินผล
- มุมมองโค้ช: ตารางของตัวเองวันนี้ + การ์ดนักเรียนก่อนเทรน (ชื่อเล่น, อายุ, **ข้อระวัง/โรคประจำตัว เด่นชัด**, ครั้งที่เท่าไหร่, โน้ตจากครั้งก่อน)
- เช็คชื่อเข้างานโค้ช + จัดการวันหยุด (ระบบกันจองโค้ชที่หยุด)

### งานขายและติดตามผล (Trial Pipeline)
- บันทึกนัด Consult/ทดลองเรียนพร้อมผล: ซื้อแล้ว / ยังไม่ซื้อ (พร้อมเหตุผล) / ไม่มา
- ระบบสร้าง task "ตามต่อ 1-2-3" อัตโนมัติตามรอบเวลา พร้อมเตือนพนักงานว่าวันนี้ต้องโทรหาใคร
- ประวัติการคุยทั้งหมดอยู่ในการ์ด Lead เดียว ไม่หายไปกับกระดาษโน้ต

### บันทึกผลการเทรน
- โค้ชบันทึกหลังจบเซสชั่น: โปรแกรมที่ทำ, ความหนัก, พฤติกรรม/ความร่วมมือของเด็ก
- บันทึกการวัดตัวตามรอบ (เช่น ทุก 4 สัปดาห์): ส่วนสูง, น้ำหนัก, ท่าทาง/บุคลิกภาพ + รูปเปรียบเทียบ

## 5. มุมลูกค้า (ผู้ปกครอง)

แนะนำทำบน **LINE OA (LIFF)** ก่อน เพราะลูกค้าไทยมี LINE อยู่แล้วและชีทเดิมก็เก็บ LINE ID อยู่แล้ว — ไม่ต้องบังคับโหลดแอปใหม่

- **จองคิวเอง** เลื่อน/ยกเลิกตามนโยบาย (เช่น ล่วงหน้า ≥4 ชม.), เห็น slot ว่างจริงแบบสด
- **กระเป๋าคอร์ส:** ครั้งคงเหลือ, วันหมดอายุ, ประวัติการเข้าเทรนทุกครั้ง (โปร่งใส ลดข้อโต้แย้งเรื่องนับครั้ง)
- **สมุดพก Growth Report:** กราฟส่วนสูง/น้ำหนักเทียบ percentile มาตรฐาน (WHO/กรมอนามัย), ไทม์ไลน์พัฒนาการ, สรุปจากโค้ชรายเดือน — นี่คือเหตุผลที่ผู้ปกครองต่อคอร์ส
- **การแจ้งเตือนอัตโนมัติ:** ยืนยันการจอง, เตือนก่อนถึงคิว, เตือนคอร์สใกล้หมด/ใกล้หมดอายุพร้อมปุ่มต่อคอร์ส, นัดวัดตัว
- **จ่ายเงินออนไลน์:** ต่อคอร์ส/จ่ายมัดจำผ่าน QR ได้เองพร้อมรับใบเสร็จทันที
- **การบ้านที่บ้าน:** คลิปท่าออกกำลัง, คำแนะนำโภชนาการและการนอน (ปัจจัยหลักของการสูง) — เพิ่ม engagement ระหว่างสัปดาห์
- **Referral & Rewards:** โค้ดแนะนำเพื่อน, แต้มสะสมแลกครั้งฟรี/ของที่ระลึก
- ให้คะแนน/feedback หลังเซสชั่น (ส่งถึงผู้จัดการ ไม่ประจานโค้ช)

## 6. โครงสร้างข้อมูลหลัก (Entities)

```
Guardian (ผู้ปกครอง) ──< GuardianChild >── Member (เด็ก)
Member ──< Enrollment (คอร์สที่ซื้อ: ครั้งทั้งหมด/คงเหลือ, วันเริ่ม-หมดอายุ, โค้ชผู้ดูแล)
Enrollment ──< Payment (งวดชำระ, ช่องทาง, เลขใบเสร็จ)
Enrollment ──< SessionCredit ledger (บันทึกเพิ่ม/ตัด/คืน/หมดอายุครั้ง — ตรวจย้อนได้ทุกรายการ)
Booking (slot, ประเภทนัด, สถานะ: จอง/มา/ไม่มา/ยกเลิก) >── Coach, Member
Lead/Trial ──< FollowUp (ตามต่อ 1-2-3, ผล, เหตุผล)
Measurement (วันที่, ส่วนสูง, น้ำหนัก, หมายเหตุ) >── Member
Coach (เรทค่าเทรน, ตารางเวร/วันหยุด) · CommissionEntry (สร้างจาก Booking ที่เสร็จสิ้น)
CourseCatalog (คอร์ส, ราคา, จำนวนครั้ง, อายุคอร์ส, ของแถม) · Promotion
Branch · User/Role · AuditLog
```

จุดสำคัญ: **ครั้งคงเหลือไม่ใช่ตัวเลขที่แก้ได้ตรงๆ แต่เป็นผลรวมของ ledger** — ทุกการตัด/คืน/แถมครั้งมีบันทึกว่าใครทำ เมื่อไหร่ เพราะอะไร

## 7. กฎธุรกิจที่ระบบต้องบังคับอัตโนมัติ

1. เช็คอินสำเร็จ → ตัด 1 ครั้งจาก Enrollment ที่เก่าสุดที่ยังไม่หมดอายุ (FIFO), ห้ามติดลบ
2. เหลือ ≤6 ครั้ง → ติดธงแดงทุกหน้าจอ + แจ้งเตือนหน้าร้านและผู้ปกครอง (แทน "ฟอนต์แดง" ในชีท)
3. คอร์สมีวันหมดอายุ (เช่น 12 เดือน = ใช้ภายใน 14 เดือน) — นโยบายขยายอายุต้องมีสิทธิ์อนุมัติ
4. No-show: บังคับตามนโยบายที่ตั้งค่าได้ (แจ้งเตือนก่อน X ชม., ยกเลิกช้ากว่ากำหนด = หักครั้งหรือไม่)
5. Booking เสร็จสิ้น → สร้างรายการค่าเทรนโค้ชตามเรทของโค้ชคนนั้นอัตโนมัติ (ตัดสินใจ: ครั้งของแถมคิดค่าเทรนไหม)
6. ความจุต่อ slot ต่อโค้ช (จากชีทคือ ~2 คน/โค้ช/slot) — เต็มแล้วเข้า waitlist
7. ทุกการแก้ตัวเลขเงินหรือครั้งย้อนหลัง ต้องใส่เหตุผล + ลง audit log

---

## 8. PDPA และความปลอดภัยข้อมูลเด็ก

- ข้อมูลสุขภาพของผู้เยาว์ = **ข้อมูลอ่อนไหว** ต้องมี consent จากผู้ปกครองเป็นลายลักษณ์อักษร (เก็บในระบบพร้อมเวอร์ชันข้อความยินยอม)
- แยก consent เรื่องการใช้รูปถ่าย/วิดีโอเด็กเพื่อการตลาดออกจาก consent การให้บริการ
- สิทธิ์เข้าถึงตามบทบาท: โค้ชเห็นเฉพาะนักเรียนของตน, หน้าร้านไม่เห็นรายงานการเงินรวม
- รองรับคำขอลบ/ขอสำเนาข้อมูล, เข้ารหัสข้อมูล, สำรองข้อมูลอัตโนมัติ

## 9. แผนพัฒนาแนะนำ (3 เฟส)

| เฟส | ขอบเขต | เป้าหมาย |
|---|---|---|
| **1 — แทน Excel ให้ได้ (MVP)** | ทะเบียนสมาชิก+ผู้ปกครอง, ขายคอร์ส+ใบเสร็จ+QR, สิทธิ์คอร์ส/ตัดครั้งด้วย ledger, ตารางจองรายวันเหมือนชีทเดิม, เช็คอิน, Dashboard พื้นฐาน, ค่าเทรนโค้ชอัตโนมัติ | ทีมเลิกใช้ Excel ได้จริงภายในเฟสเดียว ข้อมูลไม่พังจากการแก้พร้อมกัน |
| **2 — ลูกค้าและงานขาย** | LINE OA: จองเอง/ครั้งคงเหลือ/แจ้งเตือน/จ่ายออนไลน์, Trial pipeline + ตามต่ออัตโนมัติ, Growth Report, feedback | เพิ่ม conversion และ renewal, ลดงานโทรตามของหน้าร้าน |
| **3 — สเกล** | รายงานเชิงลึก (deferred revenue, LTV, funnel), referral/แต้ม, การบ้าน-โภชนาการ, หลายสาขา, e-Tax | ตัดสินใจด้วยข้อมูล, ขยายสาขา |

**Tech stack แนะนำ:** Web app (Next.js) + Supabase/PostgreSQL (auth + RLS ตามบทบาท + real-time สำหรับตารางเทรน) + LINE Messaging API/LIFF + PromptPay QR — ทีมเล็กดูแลได้ ต้นทุนต่ำ ขยายได้

## 10. คำถามที่ทีมต้องตัดสินใจก่อนพัฒนา

1. นโยบาย no-show/ยกเลิกช้า — หักครั้งไหม? แจ้งล่วงหน้ากี่ชั่วโมง?
2. คอร์สมีวันหมดอายุจริงไหม (ชีทยังไม่ระบุ)? ขยายได้ในกรณีไหน?
3. ครั้งโอนระหว่างพี่น้อง/เพื่อนได้ไหม?
4. ครั้ง "ของแถม" คิดค่าเทรนโค้ชเหมือนครั้งปกติหรือไม่?
5. กลุ่ม Teen / NP ในชีทหมายถึงอะไรแน่ (ช่วงอายุ? โปรแกรม?) — มีผลต่อการออกแบบ slot และราคา
6. จองล่วงหน้าได้สูงสุดกี่วัน? จองประจำล็อกยาวทั้งคอร์สได้ไหม?
7. เรทค่าเทรนโค้ชผูกกับระดับโค้ชหรือประเภทคลาส?
